# Milestone 9：可解释 Query Decomposition

## 1. 这个里程碑解决什么问题

此前检索器把整句话只编码、检索一次。它适合“无理由退货有几天”这类单意图问题，但复合问题
容易被其中词更强、资料更多的一半主导。例如“正常发货要多久，严重延迟又能补偿多少”同时需要
发货时效和延迟补偿两份证据；单次 top-k 并不保证两类证据都出现。

本里程碑在现有 Hybrid RAG 前增加 Query Decomposition：先识别可独立回答的业务意图，再对每个
子问题分别检索，最后以覆盖优先的方式合并。目标不是让回答更长，而是让每个问题部分都有可追踪
的证据。

## 2. 为什么这里没有用 LLM 拆分

这是一个只有 28 个知识切片、意图边界清晰的求职 Demo。当前选择确定性的领域规划器：

- 结果稳定，Gold Set 可以精确回归，不会因为生成温度或模型升级漂移；
- 不增加 API Key、推理费用和一次网络调用延迟；
- 规划器只允许已知意图和文档类型，不能动态扩大 tenant/store 或资料范围；
- 拆分原因、canonical query 和规则边界容易在面试中解释。

这不是说 LLM 永远不适合拆分。知识域扩大、表达变得开放后，可以把当前实现替换为遵循同一
`QueryDecomposer` 协议的结构化输出模型，并继续使用相同的预算、scope gate 和评测指标。

## 3. 实现设计

### 3.1 有界意图规划

`CommerceQueryDecomposer` 识别退货、换货、发货、物流异常、补偿、取消、退款到账、质保、保养
等电商知识意图。只有检测到至少两个独立意图时才真正拆分，最多保留 3 路。每一路包含：

- 稳定的 `subquery_id`；
- 机器可评测的 intent 和面向人的 intent label；
- 为知识库语言校准的 canonical query；
- 最小必要的 `document_type`。

“不是不喜欢，是商品有瑕疵”这类对比句有专门的否定保护：被明确排除的“无理由退货”不会成为
第二个检索任务。调用方若显式指定文档类型，规划器也不会越过该范围。

### 3.2 独立检索但继承全部安全门

每个子问题仍调用原有 atomic search，继续强制：

1. tenant、store 隔离；
2. document type；
3. published 状态、有效期和 Embedding 模型元数据；
4. BGE 向量 + PostgreSQL 关键词召回；
5. RRF 和绝对/相对相关性门槛。

子检索按顺序执行，而不是在同一个 SQLAlchemy `AsyncSession` 上并发查询，避免 session 并发状态
错误。Embedding 编码仍在线程中执行，不阻塞事件循环。

### 3.3 覆盖优先合并

合并器先 round-robin 取每路 top-1，再取各路后续结果，并按 `citation_id` 去重。同一引用若被
多路命中，会累计它覆盖的 subquery 和 intent。只要最终 `limit` 不小于子问题数，每个已解决的
子问题就至少保留一条证据。`limit=1` 时无法承诺覆盖两个意图，这是 API 预算的明确边界。

### 3.4 可解释输出

`/knowledge/search` 和知识工具原始结果现在包含：

- 是否拆分及拆分原因；
- 每个 canonical subquery、intent 和 document type；
- 每条命中覆盖了哪些 subquery/intent；
- 哪些子问题没有可靠证据。

这些字段会进入 Agent Trace，便于判断是规划错误、某一路召回失败，还是后续生成没有使用证据。
客户回答仍只展示必要的资料标题、版本和内容，不暴露内部规划细节。

## 4. Gold Set 如何升级

当前数据集版本为 `retrieval-gold-v1.2-human-review`。7 条复合问题显式标注
`expected_intents`，覆盖：

- 取消订单 + 无理由退货；
- 质量退换 + 退款到账；
- 无理由退货 + 换货；
- 配送失败 + 延迟补偿；
- 正常发货 + 延迟补偿；
- 订单取消 + 退款到账；
- 商品质保 + 清洁保养（跨 policy/product guide）。

Runner 新增拆分率、复合问题拆分率、非复合问题误拆分率、意图 Precision/Recall 和子问题解决率，
并在每条失败记录中保存缺失/意外意图和未解决 subquery。这样不会用“最终碰巧命中了正确文档”
替代对规划本身的评测。

## 5. 实测结果

环境：Docker PostgreSQL + pgvector，`BAAI/bge-small-zh-v1.5`，100 条 Gold Set。

| 配置 | 通过率 | Recall@3 | MRR | nDCG@5 | No-answer | Hard-negative 命中 |
|---|---:|---:|---:|---:|---:|---:|
| Hash Hybrid 基线 | 83% | 91.40% | 94.09% | 92.11% | 85.71% | 6.17% |
| BGE Hybrid | 88% | 91.40% | 94.09% | 92.11% | 100% | 1.23% |
| BGE Hybrid + Decomposition | **96%** | **95.70%** | **95.70%** | **95.21%** | 100% | **0%** |

拆分专项结果：

- 7/7 复合问题被拆分；
- 拆分意图 Recall = 100%，Precision = 100%；
- 子问题解决率 = 100%；
- 93 条非复合问题误拆分率 = 0%；
- holdout 通过率从 92% 提升到 96%；
- 全量 p95 检索耗时为 12 ms（首条包含模型冷启动，报告按同一规则统计）；
- 全量检索质量门首次全部通过，holdout 通过率保持 96%。

剩余 4 条失败是 `return_003`、`return_004`、`stale_004` 和 `compensation_005`，主要属于
单意图下相邻政策的区分/排序，并非复合问题覆盖失败。下一步应以
轻量 reranker 或更细的语义特征处理，不能继续扩大拆分规则来掩盖排序问题。

## 6. Review 后的端到端修复

本地 review 发现检索层指标通过不等于最终 Agent 一定正确使用证据，因此补了四项修复：

1. presentation 不再固定截断前 2 条；三路拆分时会把 3 份证据都传给模型和客户 sources；
2. 部分子问题无可靠命中时，只把客户可读的 resolved/unresolved 标签传过生成边界，并明确要求
   模型不得推测；内部 subquery ID 和 machine intent 仍只存在于 Trace；
3. Mock Agent 只在确定为单一资料类型时预设 `document_type`，质保 + 清洁等跨类型问题交给
   planner 为每一路分别决定类型；
4. `取消`、`到账`增加订单/退款语境约束和否定处理。明确排除的短语不会只从 planner 中删除，
   还会触发 canonical query 检索，避免原句中的否定关键词继续召回错误政策。

Gold holdout 将一条重复的退款问法替换为“不用取消订单，只想知道退款审核通过后多久到账”，并把
订单取消政策标为 hard negative。第一次实测证明仅停止拆分还不够：原句检索仍召回取消政策；加入
否定意图 normalization 后，该 case 只命中退款到账资料，并推动全量通过率从 94% 提升到 95%。

新增回归覆盖三路最终回答、跨文档类型 Agent 路径、部分证据提示、组合型 OOD、否定意图和未见
paraphrase。这个 review 也明确了评测分层：retrieval coverage、presentation boundary 和最终 Agent
回答必须分别有测试，不能用 service 层 Gold Set 替代端到端验证。

随后的人工作业 Review 将数据集升级为 `v1.2-human-review`，修正了三个标签问题：

- `refund_008` 原问法只说“退货”，不足以断定质量问题，因此改写为明确的质量问题、审核材料与
  退款到账复合问题；
- `no_answer_005` 的理由补充为公司财务数据既超出店铺客服知识范围，也不应向顾客披露；
- `compensation_003` 保留“物流慢了客服能直接发券吗”的真实口语问法，但将物流停滞规则从
  hard negative 调整为弱相关 1。它能提供背景处理，只有延迟补偿规则能直接回答发券条件。

调整后真实 BGE 全量通过率为 96%，hard-negative 命中率为 0%。`compensation_003` 虽然通过，
但因弱相关资料排在直接相关资料之前，该案例 nDCG 仅为 0.7098，排序惩罚仍被保留。

## 7. 面试时可以怎么讲

一句话版本：我没有让 LLM 直接自由拆问题，而是在 Hybrid RAG 前加了一个受预算和知识域约束的
可替换规划层；每路检索复用原有安全过滤，合并时显式保证意图覆盖，并用独立 Gold intent 标签
证明 7 个复合问题全覆盖、0 个普通问题误拆分。

如果被追问取舍，可以强调：这个阶段优先可解释和可评测；接口已经抽象，未来切换 LLM planner
时仍必须输出结构化 intent、遵守最多 3 路预算，并通过现有的误拆分与覆盖指标。
